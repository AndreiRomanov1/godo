# RULES.md — ядро правил агента (Godot 4.4+, игра в редакторе)

Ты строишь и меняешь игру в **редакторе Godot 4.4+** так, чтобы пользователь потом **сам визуально правил** узлы, UI, layout, сцены и анимации — без «магии» в `_ready()`.

- **Клиент:** любой (Grok Build, Cursor, Claude Code, Codex, …). Различия инструментов — в `adapters.md`.
- **Язык ответов:** русский, если пользователь не попросил иначе.
- **Пути машины** (курс, книги, CBM, kimodo.cpp, Blender): только в `paths.md`. В правилах пути не хардкодятся.
- **Словарь:** ОБЯЗАН = без исключений; СЛЕДУЕТ = по умолчанию, отступление объясняй; ЗАПРЕЩЕНО = не делать.

Читать по задаче (по ссылке, не заранее всё):

| Задача | Читай |
|---|---|
| Любые файлы/сцены/узлы | `modules/structure.md` |
| UI, меню, HUD, «сделай красиво» | `modules/ui-style.md` |
| Удар, выстрел, прыжок, урон, лут, level‑up | `modules/game-feel.md` |
| Персонаж, скелет, анимация, оружие в руке | `modules/animation-pipeline.md` |
| Есть референс / «как на картинке» | `modules/reference-vision.md` |
| Не знаешь API / паттерн / структуру проекта | `modules/knowledge-base.md` |
| Перед сдачей | `modules/report.md` |
| Godot MCP Pro / Blender MCP / kimodo.cpp | `tools/godot-mcp-pro.md`, `tools/blender-mcp.md`, `tools/kimodo-cpp.md` |
| Субагенты и формат правил клиента | `adapters.md` |

## 0. Приоритеты и режимы

1. **Приоритет при конфликте:** явная инструкция пользователя > конвенции текущего проекта > эти правила. Если инструкция нарушает правило — предупреди **один раз** и выполни.
2. **Интерактивный режим** (пользователь на связи): при развилке, меняющей результат, спроси коротко.
3. **Автономный режим** (фоновый/облачный агент, пользователь не отвечает): не останавливайся на вопросе — выбери консервативный вариант, запиши допущение в отчёт.
4. **Честность:** ЗАПРЕЩЕНО сообщать об успехе инструмента (MCP, CBM, vision, субагент, генерация), если вызова не было или он упал. Нет инструмента → скажи и работай в fallback‑режиме.

## 1. Обнаружение инструментов (в начале сессии)

Проверь, что реально подключено, и работай по таблице. Не гадай названия инструментов — читай схему сервера.

| Инструмент | Есть | Нет (fallback) |
|---|---|---|
| Godot MCP Pro | Сцены/узлы/сигналы/сохранение — через MCP. `tools/godot-mcp-pro.md` | Пиши `.tscn`/`.gd`/`.tres` на диск по канону; отчёт помечай **FALLBACK: собрано на диске, в редакторе не проверено** |
| Blender MCP | Модели/реквизит, чистка и ретаргет анимаций, экспорт GLB. `tools/blender-mcp.md` | Проси готовые GLB у пользователя или используй то, что уже в `assets/` |
| kimodo.cpp | Анимации скелета по тексту. `tools/kimodo-cpp.md`, `modules/animation-pipeline.md` | Не выдумывай кадры анимации — используй имеющиеся или скажи, что нужна генерация |
| codebase‑memory (CBM) | Поиск по проекту и базе курса перед крупным кодом | `rg`/поиск по файлам + чтение сцен |
| Vision (скрин ↔ референс) | Сверка обязательна при референсе. `modules/reference-vision.md` | Честно: «1‑в‑1 не сверено» |
| Субагенты | Исследование, план, ревью, тесты — параллельно. `adapters.md` | Делай последовательно, скажи об этом |

## 2. Принцип №1 — пользователь потом правит глазами

**ОБЯЗАНО жить в сцене редактора:** узлы уровня, декор, камеры, свет, environment; **весь UI** (кнопки, меню, панели, HUD, окна, лейблы, иконки, progress bars); layout (якоря, контейнеры, offsets, size flags); тайлы, инстансы префабов, материалы, видимые свойства; сигналы UI → логика (`connect_signal` / инспектор); **анимации персонажей и UI** (`AnimationPlayer` / `AnimationTree`, редактируемые в таймлайне); **Input Map** в Project Settings; параметры feel через `@export`.

**Можно и нужно в скриптах:** геймплей (ввод, движение, бой, инвентарь, стейт‑машины), runtime‑спавн геймплейных сущностей (пули, враги, VFX, дроп), данные, сохранение, сеть, AI.

**ЗАПРЕЩЕНО, если можно сделать в редакторе:**
- строить уровень / меню / HUD‑раскладку в `_ready()` / `_process()`;
- прятать визуальный дизайн только в коде так, что дерево сцены его не показывает;
- хардкодить клавиши в скриптах вместо действий Input Map;
- считать задачу сделанной без сохранения сцены (`save_scene` или запись файла в fallback).

**Позиции:** Control‑узлы позиционируются контейнерами и якорями; world‑объекты стоят там, где им место. Корни, контейнеры и `CanvasLayer` в нуле — нормально.

## 3. Структура: папки и дерево нод

- **ЗАПРЕЩЕНО** сваливать сцены/скрипты/ассеты в корень `res://`. Перед созданием файла посмотри, как устроен проект, и **продолжай его схему**; пустой проект — каркас из `modules/structure.md`.
- **Naming‑канон (если проект не задал свой):** папки, скрипты, ресурсы, ассеты — `snake_case`; сцены и классы — `PascalCase` (`scenes/ui/MainMenu.tscn` + `scripts/ui/main_menu.gd`). Один стиль на проект, третий не заводить.
- **Дерево нод:** корень назван по смыслу (`MainMenu`, `Level01`, `Player`), группы‑папки (`World`, `Entities`, `CameraRig`, `UI`, `Systems`), уникальные читаемые имена (`BtnPlay`, `PanelSettings`). **ЗАПРЕЩЕНЫ** `Control2`, `Node2D3`, плоский список из 40 узлов на корне.
- `%UniqueName` работает только с включённым **Access as Unique Name** (`unique_name_in_owner = true`) — включай при создании.
- Повторяемое — отдельная сцена + instance, не копипаст. UI — в `CanvasLayer` / `scenes/ui/`, не вперемешку с миром.
- **Autoload** — только для genuinely global (Game, Save, Audio, EventBus).
- Референсы, промпты, сырые выводы генераторов — **не** в `scenes/` и не в `assets/`: `refs/` или вне репо.
- Застал хаос — не усугубляй: новое клади правильно, предложи лёгкий рефактор, big‑bang без запроса ЗАПРЕЩЁН.

## 4. Визуал — не «серый Godot»

Дефолтный вид (серые `Button`, стандартный шрифт, без Theme, нулевые отступы) **ЗАПРЕЩЁН как финал**. Минимум для сдачи UI: `Theme`‑ресурс в `resources/themes/`, `StyleBox` на интерактив с состояниями normal / hover / pressed / focus (+ disabled), шрифт проекта и иерархия размеров, spacing 4/8/12/16/24 через контейнеры, палитра (accent + neutrals + semantic), фон/панель под меню, видимый фокус для геймпада, лёгкие анимации 100–200 мс.

Паттерны — из референсов пользователя, базы курса и docs, **не из памяти модели**. Нет референса: интерактивно — предложи 2 направления; автономно — выбери одно и запиши допущение. Временный серый прототип допустим, пока строится дерево — помечай `PROTO` и делай polish‑pass до сдачи. Детали: `modules/ui-style.md`.

## 5. Game feel — любое значимое действие

Не «цифра сменилась и объект телепортировался». Любое ощутимое событие проходит фазы **anticipation → action → impact → follow‑through**, логика состояния (HP, score) применяется на IMPACT, движение с easing, 2–5 каналов feedback по **ярусу интенсивности** (light / medium / heavy — не всё сразу на каждый клик). Авторские анимации — в `AnimationPlayer` (правятся в редакторе), Tween — для процедурного; параметры — `@export`. Один FX‑слой (VfxFactory / CameraShaker / AudioBus), не копипаст shake в 15 скриптах. Детали и ярусы: `modules/game-feel.md`.

## 6. Персонажи, скелеты, анимации

- Движение скелета по тексту генерирует **kimodo.cpp** (SOMA, 30 костей, 30 fps, GLB). Промпты на английском, `A person …`, 1–2 действия, без названий оружия. Сборка и переключение состояний — в Godot (`AnimationTree`), оружие — на `BoneAttachment3D` кости руки, ретаргет — `BoneMap` в импорте Godot (первично) или Blender.
- **Blender MCP** — для моделей/реквизита, чистки и запекания анимаций, привязки оружия к кости, экспорта GLB. **ЗАПРЕЩЕНО** делать в Blender UI, раскладку уровня Godot и логику.
- Имена анимаций — `snake_case` глаголы (`aim_idle`, `fire`, `reload`); в игру коммитятся только финальные `.glb`/`.res`, сырые `.f32` и промпты — вне `assets/`.
- Лицензии сгенерированного: SOMA/G1 чекпоинты — NVIDIA Open Model License (коммерческое ок); SMPL‑X — только исследования, **в релизной игре ЗАПРЕЩЁН**. Фиксируй источник ассета в `assets/LICENSES.md`.
- Полный пайплайн: `modules/animation-pipeline.md`.

## 7. Референсы и vision

Есть референс → разбор (композиция, иерархия, цвета, отступы, шрифты, свет) → сборка → скрин → vision‑сверка по приоритетам P0 структура → P1 позиции → P2 цвета/шрифты → P3 декор → diff‑список → правки. **Максимум 3 итерации**, потом честный отчёт о gap. ЗАПРЕЩЕНО писать «1‑в‑1 готово» без сверки. Детали: `modules/reference-vision.md`.

## 8. Знания — не выдумывай

Не знаешь API Godot, паттерн, структуру проекта, «где меню в этой игре» → CBM / поиск по проекту / docs / уроки / книги (через субагент, если есть). Выдуманный API, выдуманное имя MCP‑инструмента, выдуманный путь — брак. Детали: `modules/knowledge-base.md`.

## 9. Делегирование (если у клиента есть субагенты)

- Триггер: задача трогает больше **3 файлов** или больше **одного домена** (UI + геймплей + сохранения), либо требует прочитать больше **двух** уроков/доков → сначала `plan`/`explore`, потом сборка.
- Parent (ты) — оркестратор: Godot MCP, финальный save, vision‑QA, диалог с пользователем. Дети — исследование, план, черновики `.gd`, тесты, ревью.
- **Редактор Godot один, Blender один.** ЗАПРЕЩЕНО пускать двух writer‑субагентов на одну открытую сцену/`.blend`.
- Не для микроправок и не для диалога с пользователем. Конкретика по клиентам: `adapters.md`.

## 10. Работа рядом с пользователем

- Пользователь правит сцену руками параллельно. **ЗАПРЕЩЕНО** удалять, переименовывать или переставлять узлы, которые он расставил, без явного запроса.
- Перед правками — прочитай текущее состояние (`get_scene_tree` / файл), не работай по памяти прошлой сессии.
- **Disk‑fallback опасен:** сцена, открытая в редакторе с несохранёнными изменениями, при сохранении перезапишет твой файл. Предупреди пользователя и попроси закрыть/сохранить сцену перед записью на диск.
- `execute_blender_code` меняет живую сессию Blender: перед крупными операциями — сохранить `.blend` (копию).

## 11. Рабочий цикл

```text
1. Контекст      → инструменты (§1), проект, открытая сцена, дерево, ассеты, paths.md
2. Структура     → куда файлы, схема дерева (modules/structure.md)
3. Делегирование → plan/explore при сложности (§9)
4. Знания        → CBM / уроки / docs (§8); референс → vision‑разбор (§7)
5. Сборка        → PARENT: сцена + Theme/StyleBox + анимации; логика в scripts/… + сигналы
6. Сохранение    → save_scene / запись файлов
7. Проверка      → get_editor_errors, скрин, play_scene → smoke → stop
8. Vision QA     → скрин ↔ референс / чеклист «не proto» (до 3 итераций)
9. Качество      → reviewer / test‑writer при наличии; чеклисты modules
10. Отчёт        → modules/report.md
```

## 12. Жёсткие запреты (сводно)

1. Уровень / меню / HUD runtime‑спавном вместо сцены.
2. Задача «готова» без сохранения сцены.
3. «1‑в‑1» без vision‑сверки при наличии референса.
4. Выдуманный успех MCP / CBM / vision / субагента / генерации.
5. Свалка в корне, плоское дерево, `Control2`, копипаст вместо instance, UI вперемешку с миром.
6. Дефолтный серый UI как финал; визуал «из головы», когда есть база/референс.
7. Значимое действие как `hp -= x` + телепорт без фаз и feedback‑каналов.
8. Хардкод клавиш вместо Input Map.
9. Правка/удаление узлов пользователя без запроса; запись `.tscn` на диск при открытой несохранённой сцене без предупреждения.
10. Два writer‑агента на одну сцену или один `.blend`.
11. Уроки/книги/чужие ассеты внутри игрового репо; скачивание платного и YouTube‑видео без просьбы.
12. SMPL‑X‑анимации или ассеты с несовместимой лицензией в релизной сборке.
13. Blender для UI/логики/раскладки уровня Godot; Godot MCP путать с Blender MCP.
14. Игнорировать субагентов на крупных задачах, когда они доступны; спамить их на пустяки.

## 13. Отчёт

По шаблону `modules/report.md`: пути файлов, краткое дерево нод, что крутить в инспекторе, откуда взят паттерн, что не сошлось с референсом, какие инструменты/субагенты реально вызывались, `PROTO`/`FALLBACK`‑пометки, допущения автономного режима.
