# reference-vision.md — референсы и vision‑сверка

## 1. Когда vision ОБЯЗАТЕЛЕН

- Есть референс‑изображение (фото, скрин, UI‑макет, кадр из игры).
- Просьба «как на картинке» / «1‑в‑1» / «UI по фото».
- Крупная визуальная сборка (меню, HUD, уровень, персонаж с оружием) — контроль качества.

Источники скринов: Godot — `get_editor_screenshot`, `play_scene` + `get_game_screenshot`; Blender — `get_viewport_screenshot`; клиенты без MCP — скрин от пользователя.

## 2. Работа с референсом

1. Найти и прочитать файлы референса (`paths.md: REFS`).
2. Разобрать: композиция, UI‑иерархия, цвета, отступы, шрифты, камера, свет, поза персонажа.
3. Собрать в редакторе (структура по `modules/structure.md`, стиль по `modules/ui-style.md`).
4. Сохранить, снять скрин, сверить по §3.
5. Diff‑список правок → правки → снова скрин.
6. Стоп по §4. Отчёт: совпало / отличается и почему.

## 3. Приоритет совпадения и допуски

| Приоритет | Что | Допуск |
|---|---|---|
| P0 | Структура экрана/сцены, наличие элементов, порядок, читаемость | без расхождений |
| P1 | Позиции, размеры, отступы, выравнивание | ±8 px при 1080p (или ±0.5 % ширины) |
| P2 | Цвета, прозрачность, скругления, тени, шрифты | визуально неотличимо на скрине в масштабе 1:1 |
| P3 | Мелкий декор, постэффект | нет ассета → сказать, предложить замену |

## 4. Цикл и стоп‑условия

```text
1. Референс → vision‑разбор
2. Сборка (MCP / fallback)
3. save_scene
4. Скрин
5. Vision: референс ↔ скрин по §3
6. Diff‑список (конкретно: узел, свойство, было → надо), не «почти»
7. Правки → снова 3–6
СТОП: P0–P2 закрыты | упёрлись в ассет | пользователь принял | прошло 3 итерации → отчёт о gap
```

Автономный режим: после 3 итераций не продолжать — зафиксировать оставшийся diff в отчёте.

## 5. Шаблон запроса к vision

- «Сравни референс `<путь>` со скрином `<путь>`. Оцени по P0 → P3. Выдай diff‑список: узел / свойство / текущее / целевое».
- Для персонажа с оружием: «Совпадают ли поза, положение рук на оружии, приклад у плеча, направление ствола? Что сдвинуть в `WeaponSocket`?»

## 6. Честность

Нет скрина или vision недоступен → «1‑в‑1 не сверено», без выдуманного прогона. Разбор референса и diff‑чеклист можно отдать субагенту; финальные правки, save и решение о готовности — у parent.
